# Layer Assembly — Project Memory

Sub-memory of Design + Toolpath (see `../PROJECT_MEMORY.md` for the Designer). Kept separate so Z / stacking / 3D-preview work can iterate without reading or retesting Designer internals.

Structure: CURRENT ARCHITECTURE → DESIGNER CONTRACT → CURRENT DECISIONS (by topic) → KNOWN LIMITATIONS → TESTING → NEXT STEPS → HISTORY (superseded approaches, compressed). All of this is uncommitted work of 2026-10-06, audited and cleaned for the checkpoint.

## Purpose

Assemble reusable 2D LAYER DESIGNS (made with the Designer) vertically into a printed form: which design is used at each Z, where every layer sits, and whether every layer is physically supported.

    DESIGNER        — reusable 2D Layer Designs (walls, trims, openings, lattice, beads, routes)
        ↓ LayerSource (designer_source.py — the only Designer import)
    LAYER ASSEMBLY  — sections by physical height → layer instances + Z + transforms;
                      transform groups → semantic variants; ASSEMBLY PROFILES → per-layer
                      source cuts (cut variants); vertical support + headers
        ↓ future
    PRINT / MACHINE OUTPUT (Z, G-code, Pi) — not started

## Designer ↔ Assembly contract

- **Assembly asks:** `geometry(design_id)` (canonical) or `geometry(design_id, transforms={source id: (k, tx, ty)})` — a SEMANTIC VARIANT: the layer's group placements relative to its own placement, applied to SOURCE PATHS by the Designer. There are no cross-Z hints in the contract: the Designer tracks a variant's lattice against the untransformed design itself.
- **Designer returns** `LayerGeometry(design_id, polylines, bead_width, diagnostics, sources)`: printable polylines each with `src` (per-vertex source path id — source_attribution.py), the project bead width, diagnostics {lattice (incl. lineage), trims, semantic {connectors, moved, junctions}, timing}, and source labels.
- **Caching:** `web._SOURCES` (LRU 4) keyed by the full designs JSON → one `DesignerSource` per design set; inside it canonical geometry (`_plain`) and variants (`_variants`, LRU 512, key = design + `semantic_transform.spec_key`). The Designer library caches builds (`_cache`, `_tbuilds`) and content-keyed scaffolds / documents (`layer_design._SHARED`, `_TRACK_MAPS`, `semantic_transform._WALLS`, `_RELATIONS`). Variants are prefetched in spawned worker processes (`LAYER_ASSEMBLY_WORKERS`, default min(8, cores); 0 = in process; falls back in process).
- **Needs a fresh Designer resolve:** any designs change (geometry, openings, lattice, material — bead width included) → new DesignerSource, every design and variant rebuilt; a transform change that produces a NEW source-transform spec (only those variants).
- **Needs NO Designer resolve:** layer height without group transform change in footprint mode, Maximum overhang, headers, overrides, renames (names are outside the cache key), section reorder that keeps specs.
- **Placement:** every vertex of a layer is placed by the layer's own `InstanceTransform`; a vertex's group gives only its local FRAME (finding / header coordinates). The Assembly never moves resolved beads per vertex (the abandoned rubber-sheet approach — see History).
- **Profiles (2026-10-08) extend the contract:** `geometry(design_id, transforms=None, cuts=None)` — `cuts` = the layer's cut spec (`[{'op': 'opening', 'source', 'edge', 'at', 'width', 'profile'} | {'op': 'extent', 'source', 'edge': None, 'end', 'retained', 'profile'}]`), applied by the Designer to the design DOCUMENT before the transforms (`design_proto/profile_cuts.py`); and `walls(design_id)` → the straight walls a profile can target; `openings(design_id)` (2026-10-09) → the design's authored openings on straight edges (id, source, edge, at, width — what a conversion refers to) (`source, edge, a, b, length, thickness, taper, min_length, label`). Variant cache key = (design, transform spec, cut key); `LayerInstance.geometry_key` appends `|cut:…` (cut ops: 'opening', 'extent', and 'station' = no cut, the lattice reference of an Assembly opening's wall); `is_variant` / `cut_spec()`; `source.variant_request` / `layer_geometry` are the one place that turns an instance into a geometry request (preview, `stack_geometry`, web). Worker processes take cuts too. A profile edit needs NO new DesignerSource (designs unchanged): only layers whose cut changed are resolved (variants of equal width are shared). Planar top cut (2026-10-08): `sources(design_id)` → every selectable wall {source, label, closed, system, system_label, points (coarse centre line)} (`profile_cuts.source_list`; web response `profile_sources`); `apply_profiles(…, sources)`; cut op 'plane' + plane 'station' ops.

## Current decisions

### Stack resolution
- Sections are given by desired PHYSICAL height; layer counts are derived by rounding section BOUNDARIES (cumulative height / layer height, half up): every transition within ½ layer of its Z, no accumulation; a section rounding to 0 layers is warned. Changing the layer height re-resolves the same intent.
- Instances only REFERENCE a design (Base used for 40 layers exists once).

### Transforms
- `SectionTransform(profile, shift=(dx, dy), scale_in)`, amounts PER LAYER, inputs step 1/16 in (stored as typed). Per layer: scale about the CURRENT footprint centre, then translate (physical inches, never scaled). Each section continues from the previous section's END state (position continuous; slope not matched — known).
- Profiles: linear m = k; quadratic m = k(k+1)/(2n) — v is the FINAL per-layer rate (a plain v·k² was rejected as unintuitive).
- SCALE is a uniform scale (relationships preserved; bead spacing / thickness scale with the WHOLE layer). A true constant-thickness inset would be a Designer re-resolve behind the LayerSource boundary (not built).
- Assembly-wide transform: the same model over the whole stack (n = all layers), composed geometry → assembly-wide → section → placement, both shifts physical, scales multiply; identity = section-only behaviour exactly.
- Result: ONE `InstanceTransform` per layer, consumed identically by preview, support, headers and (future) machine output.

### Transform groups (semantic)
- `center_mode`: 'footprint' (default, one pivot) | 'multiple'. A `TransformCenter` moves EXACTLY its explicitly assigned source walls (`sources`, the Designer source path ids — stable across derived designs and openings). First listing wins (warned); unassigned walls follow the whole footprint; moving a pivot never changes membership; no nearest-centre / Voronoi rule anywhere. Components only suggest.
- **Principle (durable): transform the architectural relationships, then resolve.** Per layer the Assembly computes each group's placement relative to the layer's own and asks the Designer for the variant. Walls keep ONE physical thickness (only the whole layer's placement scales it); connecting walls are regenerated by the Designer, never stretched.
- Explicit connectors (an authored wall attached to moved forms) are regenerated between their transformed attachments; DERIVED junctions (forms that merely intersect) are recomputed from the transformed forms and disappear when they separate — both reported per variant (`connectors`, `junctions`) and listed in the Assembly Transform column.
- Identity is exact: near-identity placements request nothing, the layer prints the canonical design.
- Colours are diagnostic in Multiple mode: assigned geometry = its group colour, UNASSIGNED = the Designer blue `#4a9eff` (no blue in the group palette).

### Vertical support
- **Rule: mud requires physical support below** — from the layer directly below or an explicit assembly object. No door special case.
- **Input: Maximum overhang h** (`Assembly.max_overhang`, default 1.5 in, ≥ 0). Required overlap per transition o = w_u − h (h clamped to [0, w_u], warned); the report carries the derived `min_overlap`. The bead width is the Designer's project material (Base's `material.bead_width`), never Assembly state.
- **Math:** parallel beads w_u, w_l offset d overlap min(w_u, w_l, (w_u + w_l)/2 − d). Quick accept within the allowed centreline offset; otherwise the EXACT covered length of the upper bead's cross-section by the union of lower capsules (both legs measured at a vertex). Sampling every ½ bead; regions within 4 beads merge; < 2 beads is noise.
- **Classification:** HEADER NEEDED (`bridge`) when along an unsupported run ≥ 1 bead lies over an EMPTY CORRIDOR (w_u + 2·w_l across the strand touches no lower bead) or nothing lies within 2·w_u; otherwise INSUFFICIENT LAYER SUPPORT (`overlap`, required vs worst overlap). Geometry only.
- **Aggregation:** `SupportReport.groups()` — one group per kind / status / section / place (contiguous or scattered layers); one card and one viewport label per group; headers stay individual. Ignore records a whole group.
- **Headers** (`objects.Header`): anchored at a layer boundary in that layer's local coordinates (follows transforms); length = span·scale + 2·bearing; snaps to the detected span; top at the boundary, hanging down `thickness`; pockets REPORTED, not cut. Created only from a warning. Overrides (section, local layer, centre) mark a finding `overridden`, never supported.
- **The support checker is a test of the geometry: never weaken it to hide findings.**

### Undo / redo
- Separate from the Designer's (`asm.hist`, 200 steps): snapshots of the Assembly state + header counter + design names + bead width; edits of one field within 1.5 s merge; a drag is one step. Profiles are part of `asm.state` (`profiles`, `profile_counter`): create / edit / handle drag / delete are Assembly undo steps.

### Assembly Profiles (2026-10-08; uncommitted, for manual review)
- **Rule (durable):** Assembly Profiles determine what SOURCE wall geometry survives at each Z. They resolve into ordinary 2D layer geometry (Designer openings / shortened source walls), which then goes through the existing Wall System / lattice / opening / routing machinery. They never generate or edit toolpaths, and are a subsystem separate from Assembly Transform (which is behaviourally unchanged).
- **Integration point (least invasive, found by inspecting the pipeline):** the semantic-variant path. `resolve()` is untouched (placements from canonical footprints); `profiles.apply_profiles` attaches a per-layer CUT SPEC afterwards (`LayerInstance.cuts`); a layer with cuts prints a CUT VARIANT exactly like a grouped layer prints a semantic variant (`DesignLibrary.build(design, transforms, cuts)`; `_tbuilds` cache, closure verdict, planned-alone fallback, tracking against the canonical plan).
- **Resolution order per layer:** Layer Design document (inheritance) → PROFILE CUTS (design coordinates, untransformed sources: `profile_cuts.apply_cuts`) → semantic transform of transform groups (an Assembly opening's position scales with its host, its width stays physical — as for any Designer opening; a shortened wall is moved like any wall) → normal Designer resolution → the layer's InstanceTransform (section / assembly-wide). Profiles never change placements.
- **Data model** (Wall Taper UI removed 2026-10-08 — see Planar Top Cut; `Assembly.profiles`, serialised in `to_dict` / `from_dict`; older states → []): `OpeningProfile(id, wall: WallRef, position, z_bottom, height, width, shape 'diamond' | 'lens', label)`; `ExtentProfile(id, wall, keep 'start' | 'end', knots ((z, s) …), interp per span 'linear' | 'step', label)` = a CUT PROFILE in the wall's elevation: s = the cut position in inches from the wall's START point at height z, `keep` = the retained side (the other side disappears layer by layer; `end` property = the retreating end for the Designer's cut spec, retained = s or L − s). The cut points are authoritative — nothing ties them to the wall's ends, so a short local buttress taper is two points near the free end. Below the first point: unaffected; above the last: the cut holds (vertical). The general piecewise representation (stairs / shelves later: more knots, 'step'); V1 UI = `taper(id, wall, keep, s_lower, z_lower, s_upper, z_upper)` (two points, linear). **Revised 2026-10-08 after manual review** — previously `end` + knots of RETAINED length, created corner-to-corner [[0, L], [top, 0]] and edited as "kept at lower / upper": that model always measured from the architectural end, the 'end' default could retreat the ATTACHED end of a buttress (detaching it — the "broken geometry"), and the drawn red diagonal did not read as a cut. Pre-revision dicts with end 'end' still load (same numbers); end 'start' is refused (no project files exist).
- **Locality (2026-10-08 correction):** a cut variant prints the UNCUT layer's lattice clipped at the new end walls and joined pairwise on them (Designer: `DesignLibrary._cut_join`, `model._join_cut_ends`) — geometry changes only within one wall thickness of a cut face; falls back to the earlier lineage / tracked re-plan only if that route cannot close. **Single-pass runs:** a lattice run printed by ONE pass (a room ring with no junction, a run between junctions — e.g. the demo Base alone) cannot be clipped and closed locally: the opening cuts that one strand once per cut face (an odd end each — parity). So a valid opening profile adds a `('station', source, edge, at, 0, pid)` op (no cut) to EVERY layer of every design that has the wall; the Designer (`DesignLibrary._station_reference`) probes the uncut reference with a ½ in cut at each station and, only where it cannot close, re-plans the reference with lineage jamb stations there (+ the family's lines), tracked against the uncut plan — the run then carries two mirrored passes on every layer of the stack, cut or not, exactly as a Door Gap derived design makes its Base do. Cost: layers outside the profile's Z range of that design print the doubled run too (one shared variant); an assembly WITHOUT profiles is unchanged. Demo room (Base only, 30 × 60 diamond): 9 findings → 0. Root cause of the review failure (hole looked absent, lattice reorganised far away, remote purple / HEADER NEEDED findings): a cut shortens a wall RUN and the lattice planner fits its stitches to the whole run segment, so every stitch of the wall moved on every cut layer. The "invisible hole" itself: in an elevation every parallel wall projects onto the same place, so in a room the opposite wall's lines covered the cut — the elevation now dims geometry farther than ½ thickness + 2 beads from the profiled wall (`_asmElevationFocus`; orbiting away shows everything).
- **Generated Wall Systems keep their cross-Z phase at cuts (review 3):** Interleaved / Linked / Chained Loop used to be generated per piece — period re-fitted to each piece's length, phase anchored at each piece's start — so a taper / opening re-phased the whole wall on every layer (the reported chaotic waves + false findings). Now the uncut layer's generation records a FRAME per run (`wall_systems` report 'frames' → `BuiltLayer.ws_frames`), and a cut variant passes them as `PrintLayer.wall_system_reference` → `wall_systems.generate(…, phase_ref)`: each run is mapped onto the reference run it lies on (s_ref = ±s + β, fitted on interior samples; across sign compared), drawn with the REFERENCE span period / phase / lanes (Interleaved / Linked) or the reference loop curve (Chained Loop); only NEW free ends are solved locally — waves fade into the canonical end lanes over ½ thickness (original ends keep the reference fade and station), the chain is clipped where the reference curve leaves the usable length and leads out to the cap. Measured (240 in line): away from the cut every layer equals the uncut pattern to ≤ 0.02 in (sampling); changes within ~1 thickness (waves) / ~1.5 thickness (chain) of the cut. Findings: Linked opening 6 → 1, Linked taper many → 0, gentle tapers (≤ ~0.75 in / layer) Interleaved / Linked 0, Chained Loop 1; remaining: the end motif at the narrowest first / closing cut layers (Interleaved 1, Linked 1, Chained Loop 3 per Diamond) and at FAST retreats (≳ 1 bead / layer: the end motif moves too far per layer; also with the old re-fit). Chained Loop alternatives measured and rejected: clip at loop boundaries, clip by mean progression, end warp over 2–5 pitches (11–44 findings vs 10).
- **PLANAR TOP CUT = THE general planar taper / cut (2026-10-08, second pass):** (1) **Wall Taper is no longer a tool** — the Profiles column offers only "+ Self-supporting opening" and "+ Planar top cut" (a plane on one wall does what the taper did). `ExtentProfile` stays in the model (older states resolve as before) and shows as a LEGACY card with "Convert to planar top cut" (`asmTaperToPlane`: the plane through the taper's cut line, rising toward the kept side; one undo step; it extends the line below the lower / above the upper point — tested: every in-range layer identical to the taper). (2) **Plan position is its own degree of freedom:** nothing re-spans the plane over the footprint. The handle is the TOP CONTOUR ("cut begins": where the plane meets the stack top) — drag it (or "Cut begins" in) to translate the plane along the uphill direction, slope kept; drag the arrow tip (or "Uphill dir.") to turn it about that line's point nearest the selection centre; Slope / Rise-run pivot about the same line; Flip = 180° about it. "Z uphill / downhill edge" remain as explicit readouts / edits. So a plane can clip only one corner of a flat building. (3) **Several planes compose subtractively:** the Designer applies all plane ops of a layer TOGETHER (`profile_cuts._apply_planes`: per source the union of every selecting plane's removed stretches, then one cut). Each plane keeps its own selection / position / slope (editing or deleting one never changes another's cut ops — tested). Geometry rules added while making corner cuts work: a ring whose removed stretch contains a CORNER (or where a wall attaches) is cut into its KEPT STRETCHES — the first keeps the source id, others become sibling sources `<id>~p<k>` (same Wall System, an owned web cloned `<web>~p<k>` and clipped from the original web's reference) — on the ring's EXACT line with its wall side as an explicit `align_override` 'left' / 'right' (a closed wall's inside / outside means nothing on an open path; *superseded 2026-10-08 third pass: the pieces used to be offset half a thickness and centred — that moved their contacts off the other walls' lines, so trims / junctions at those contacts changed far from the cut*); CORNER MINIMUM: a removed or kept stretch reaches at least one wall thickness along each leg of a corner (square cut faces closer to a corner cross inside the wall) — those layers remove a little more, their terminations lie below the plane (reported `corner_min`); STUBS: an opening overlapping a removed stretch merges into it and no piece shorter than the construction minimum is left between a cut and an opening; order in `apply_cuts`: extents → openings / transitions → planes → removed sources. ### Lift-aware print planning (2026-10-09; uncommitted, not yet manually reviewed)
- **Machine rule (requirement):** ~18 in usable Z travel; after a LIFT the whole XY frame is raised (major, manual, not motorized / not controlled here). Complete all printing in a lift before raising; never return to an earlier lift; inside a lift build independent islands upward as far as their geometry allows; merged geometry after all its lower parts; never descend through finished geometry; support / layer order preserved. Lift / island schedule takes precedence over travel minimisation.
- **Settings:** `Assembly.machine` {max_z_travel 18, lift_height 18 (≤ max), head_clearance 1} (in; validated by `model._machine`; saved with the project — additive key, project file schema unchanged); the frame-reposition time estimate is a TIMING setting: `print_speeds.frame` (s; 0 = not estimated) → `PrintSpeeds.frame_time` (a speed-only edit = times-only re-time). Edited ONLY in the Simulation's Print plan column (see "Print Simulation workspace" → UI).
- **Lift boundaries (`lift_bounds`):** whole layers, greedy from the bottom: a lift takes each next layer while top − the lift's first bottom ≤ lift height (1.5 in → 12 layers; 1.4 in → 12 layers = 16.8 in, remainder to the next lift; a single layer taller than the lift = error). Frame base = the lift's bottom.
- **Pieces (`layer_components`):** per layer, polylines whose centrelines come closer than one bead width (beads touch / fuse) — union-find over shared end vertices, then grid-accelerated point-to-segment proximity (samples ≤ ¾ in); from the ACTUAL resolved geometry (variants, cuts, openings, transforms, derived designs), never Wall System membership; cached per (geometry key, scale). A Hollow wall's two skins without a web ARE separate pieces (7 in apart at 10 in thickness) — raise Head clearance to keep them layer by layer.
- **Order (`lift_graph` + `schedule`):** DAG per lift: piece X (layer k) after every piece of a LOWER layer of the lift closer than bead + head clearance (support, and geometry the nozzle would descend beside); a piece with nothing under it waits for the whole layer below; links = bead contact between adjacent layers (stages, connected groups). Greedy deterministic topological order: (1) a ready piece directly above the last one (keep building the island up; nearest), (2) else the lowest ready piece of the same connected group (the other side of a later merge), (3) else the lowest ready piece; ties: the piece holding the design's manual start, nearest to the nozzle, stable key. Each chosen piece is routed immediately (`visit`) from the nozzle → the next choice uses the real end. Single-piece lifts skip the geometry tests (forced column order).
- **Stages (`stages`):** chains with exactly one link down / up: independent islands A, B, … per lift (print order), merges "A+B", split branches "A.1"; kinds island / merge / split.
- **Plan model (extends the one authoritative plan; no simulation-only planner):** Building (`PrintPlan`) → `Lift` (layers, z range, frame_z, stages, passes, `reposition_in`: `FrameMove` {from / to lift, frame z before / after, nozzle xy / z}) → `Stage` → `Pass` (one global layer's piece: lift, stage, component, z, steps, `transition_in`, manual flags) → `Run`. `plan.layers` = the GLOBAL layers (identity, z, placement, `passes`; runs / travels / transitions aggregated, run indices unique per layer); `plan.passes` = the PRINT ORDER. A global layer may be printed in several passes at different times. Transitions carry dz (− = back DOWN to another island's lower layer, same lift) and `clear_z` (the Z of the XY move: above every printed piece of the lift beside its path — for export: rise, move, descend); in-piece travels too. `moves()` / `items()` / `stream()` follow the passes, with a 'frame' item (code 4, duration = frame time) before each later lift; stream items carry lift / stage / pass / zc.
- **Routing:** a one-piece layer is routed whole exactly as before; a piece alone through `DesignerSource.route(g, start, members=…, manual_start=…)` (routing description narrowed: its Route Origins, the design start only on the piece nearest to it, component order dropped — it numbers the whole layer's components). Route Origins + reverse: every pass of the design. Existing paths are never changed; the traversal inside a piece may differ from the whole-layer Designer route (graph node order), still closed / no retrace.
- **Timing:** `duration('frame')` = frame time; `estimate` adds `frame_time`, `frame_moves`, per-`lifts` (print / travel / frame / total + stages) and per-`stages` (print / travel); totals extrusion / travel / frame separately; the Simulation clock still ends exactly at the estimate.
- **Measured (same 200-layer Interleaved + Chained Loop building as the Simulation, 17 lifts):** plan 4.1–5.4 s (was 3–5 s; piece detection 0.3 s, single-piece lifts need no proximity tests), re-time 0.84 s (was 0.5 s: more stream columns); 200-layer three-island building merging in stages ×10 (380 passes, 68 stages): plan 0.7 s, of which lift graphs 0.69 s. Simulation (headless Chrome): the three-island / two-lift building plays its schedule, frame banner + lift outline + timeline tick, top view of a three-pass layer on its own clock.
- **Limitations:** the schedule is greedy (no global optimisation of island order / travel); head clearance is one radius (no real print-head shape, no gantry); Z moves and clear-height rises are not timed; the frame is assumed raised exactly to the next lift's first layer bottom; the Designer component order is not applied across pieces; manual start picks the nearest piece; a piece's internal route may differ from the Designer view's whole-layer order.
- **Tests:** `tests/test_lifts.py` (18, with an INDEPENDENT validity checker: no earlier lift, lift heights, frame moves, every lower piece within bead + clearance printed first (brute force), each strand once — verified to FAIL with the ordering removed): lift bounds (1.5 / 1.4 / 1.0 / 2.5 in, lift > Z travel, layer > lift), settings validation / round trip, one continuous wall (2 lifts, plain order, frame move at the end position), two islands, merging halfway (A 0–5, B 0–5, A+B 6–11), three islands merging in stages, an island ending below the boundary, layer / lift heights, a Designer opening and a planar cut changing connectivity (merge / split), two Wall Systems touching = one island, transform groups growing two rings into one (+ section shift), never back to an earlier lift, merge never early (3 heights), determinism, manual start / reverse / Route Origin, timing + frame events; `test_print_plan.py` updated (islands now built one after another; ring + circle touching for the Designer-route equality); `ui_simulation_smoke.js` lift section.

## Known limitations

- **Transformed junction lattice (the main open problem):** on the reference stack (`design_proto/tests/reference_network.py`, 32 layers, Circle 1 / Rect 1 / Rect 2 in three groups scaling, round junctions) support reports ≈ 51 (zigzag) / 71 (wave) findings, ~85 % on lattice at the Rect 1 ↔ Circle 1 lens and the Rect 1 ↔ Rect 2 crossing. Every variant's route closes. Cause (Designer side): junction transitions are re-planned per layer. Precise statement and next step: Designer memory → "Transformed-junction lattice".
- Cost: each grouped layer with a new spec is a full Designer resolve (~0.9 s CPU, ~0.12 s wall with 8 workers); support analysis ~21–25 ms per layer and dominates warm edits.
- Only the layer directly below counts (no corbelling / multi-layer bridging); geometric, not structural.
- Headers / overrides keyed by section index (reorder can orphan them; reported); no header self-support check; footprints are bbox squares.
- Attachments are coincidence in the untransformed design (no persistent constraints, Designer side).
- No AUTOMATIC persistence: the project is saved / opened explicitly as a `.muddesign` file (2026-10-09); a page reload without saving still loses the work. Assembly undo history is not saved (reset on Open).
- **Self-supporting openings (2026-10-10):** straight walls only; rounded (curved) bottoms over a wall cavity still report the first-layer jamb caps (explained, not hidden); a Lens opens as the vesica (not its identical curve) and is re-constrained (usually a little taller / narrower, said on Open); the curved Diamond must be ~2.4 × taller than wide at layer height = overhang (geometry, not a bug); an opening's top must stay below the stack top (reported); constraints assume the one global layer height (true by design). Generated headers: one shared setting per profile (no per-clone header edits); placement follows the opening (no manual nudge); pockets reported, not cut; a header where no span is detected stays on the wall's SOURCE line (only drawn; nothing to carry).
- **Assembly Profiles (2026-10-08, after the correction pass):** Skin + Web webs and wall lattice infills are LOCAL at cuts (no findings measured for Diamond / Lens on Skin + Web zigzag / wave, the demo room, tapers; changes within one wall thickness of a cut face). Generated constructions keep the uncut pattern (review 3, see above); still open there: their END MOTIF at the narrowest first / closing cut layers and at fast retreats may be reported (overlap, never bridge). The local join bends the two cut strands over one end-wall length; where the clipped uncut lattice cannot close (none seen in tests), the layer falls back to the earlier re-plan (non-local). Plain / Skin openings print the Designer's clear-width convention (flat caps ON the cut face → the physical gap is one bead narrower than `width`; generated constructions are exact). Straight walls only; one opening / taper shape set; tapering the ATTACHED end of a network wall detaches it (choose Keep = the attached side). (Trims bounded by a removed / cut wall are PINNED since 2026-10-08 — their sections no longer come back.)
- **Planar top cut (2026-10-08, third pass):** a PARALLEL ring given an ordinary Opening by a cut re-connects a few lane ends elsewhere on that ring / at its junctions, and a Parallel lane end at a link junction slides ≤ ~1 in as the plane shortens the link — Designer Parallel routing, identical with and without Trim (not asserted as coherent for Parallel). Corner-minimum / chain / Hollow termination reports as listed above. Exact resolve after an edit that changes every cut layer ~2.4–4.3 s on an 80-layer generated building (the preview covers it). The live preview ignores other profiles' cuts and draws no caps. Every distinct width / cut position is a Designer build of that layer (now ~25–40 ms each through the join).
